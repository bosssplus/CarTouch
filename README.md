## ۱. معرفی پروژه

**CarTouch** یک سیستم کنترلی برای خودرو است که با استفاده از **ESP32-S3** و **CAN Bus** (شبکه داخلی خودرو) امکان کنترل و مانیتورینگ خودرو را فراهم می‌کند.

### قابلیت‌های اصلی:
- **کنترل لمسی** از طریق صفحه TFT 2.4 اینچ داخل خودرو (روش اصلی)
- **کنترل از راه دور** از طریق Web Dashboard با WiFi (روش مکمل)
- **قفل/باز کردن** درب‌ها (۴ درب + صندوق عقب)
- **بالا/پایین بردن** شیشه‌ها (۴ شیشه + سانروف)
- **کنترل آینه‌ها و دزدگیر**
- **نمایش اطلاعات خودرو** (سرعت، RPM، دمای موتور، ولتاژ باطری، سطح سوخت)
- **خواندن کدهای خطا** (DTC) از ECU خودرو
- **حالت Listen-Only** (فقط خواندن بدون ارسال فرمان)
- **Auto Sleep** بعد از ۱۰ دقیقه بی‌فعالیتی (حفظ باطری خودرو)
- **بیدار شدن خودکار** با دریافت پیام CAN
- **پشتیبانی از ۳۰۰+ مدل خودرو** از طریق OpenDBC
- **حالت شب/روز** خودکار
- **🆕 یادگیری فرمان از خودروی واقعی (Learn Mode)** — دستگاه را یک‌بار
  به CAN Bus وصل کنید، دکمه‌های فیزیکی واقعی خودرو را بزنید، و دستگاه
  پیام‌های مربوطه را ضبط می‌کند (v2.0)
- **🆕 ورود دستی CAN ID/بایت** برای وقتی این اطلاعات را از منبع دیگری دارید (v2.0)
- **🆕 چرخه‌ی تأیید ایمن**: هر فرمان یادگرفته/واردشده تا تأیید صریح
  کاربر در حالت «تأییدنشده» قفل است و قابل اجرا نیست (v2.0)
- **🆕 دیتابیس خودروی شخصی**: ذخیره/بارگذاری/اشتراک‌گذاری پروفایل‌های
  خودروی دست‌ساز به‌صورت JSON (v2.0)

## ۱.۱ نسخه v2.0 — یادگیری فرمان از CAN Bus واقعی

این نسخه یک قابلیت اساسی جدید اضافه می‌کند: **Learn Mode**. برای
مستندات کامل فنی (معماری، الگوریتم، محدودیت‌های ایمنی، و نقشه‌ی راه
توسعه) به فایل [`CarTouch_V2_SPEC.md`](./CarTouch_V2_SPEC.md) مراجعه
کنید — این فایل مرجع کامل و مستقل این نسخه است.

### خلاصه‌ی قابلیت:

هر خودرو فرمان‌های کنترلی متفاوتی روی CAN Bus دارد که در هیچ
دیتابیس عمومی (از جمله فایل‌های DBC همراه این پروژه) موجود نیست. Learn
Mode این مشکل را با یک روش کاملاً امن حل می‌کند:

1. دستگاه را به CAN Bus خودرو وصل کنید (طبق بخش ۳ همین فایل)
2. از تب «یادگیری» (در TFT یا وب) یک برچسب فرمان انتخاب کنید (مثلاً «قفل همه درب‌ها»)
3. دستگاه ۲ ثانیه پیام‌های پیش‌زمینه را می‌شنود (**بدون ارسال هیچ فرمانی**)
4. دکمه فیزیکی واقعی خودرو را می‌زنید؛ دستگاه ۲ ثانیه بعدی را ضبط می‌کند
5. کاندیدهای یافت‌شده را می‌بینید و آنی که درست بود را انتخاب می‌کنید
6. فرمان ذخیره می‌شود ولی همچنان «تأییدنشده» (⚠️) است — قابل اجرا نیست
7. با یک تأیید صریح جداگانه (که CAN ID/بایت واقعی را نشان می‌دهد)، آن
   را یک‌بار آزمایش می‌کنید و نتیجه را دستی تأیید می‌کنید
8. فقط بعد از این مرحله، فرمان در تب کنترل اصلی فعال می‌شود

**⚠️ محدودیت‌های واقعی که باید بدانید:**
- بعضی خودروهای جدیدتر (معمولاً بعد از ۲۰۱۸، برندهای پریمیوم) از کد
  متغیر (rolling code) استفاده می‌کنند که با این روش کار نمی‌کند
- تشخیص کاندیدها نیمه‌خودکار است؛ تأیید نهایی همیشه با شماست
- دستگاه هرگز به‌صورت خودکار/آزمایشی فرمان به باس نمی‌فرستد

## ۳. سیم‌بندی و اتصالات

### ۳.۱. اتصال صفحه TFT به ESP32-S3

| پین TFT | پین ESP32-S3 | توضیحات |
|---------|--------------|---------|
| **CS** | GPIO10 | Chip Select |
| **DC** | GPIO7 | Data/Command |
| **RST** | GPIO4 | Reset |
| **MOSI** | GPIO11 | SPI Data In |
| **SCLK** | GPIO12 | SPI Clock |
| **MISO** | GPIO13 | SPI Data Out |
| **BL** | GPIO21 | Backlight (PWM) |
| **VCC** | 3.3V | تغذیه 3.3V |
| **GND** | GND | زمین مشترک |

### ۳.۲. اتصال تاچ (XPT2046)

| پین تاچ | پین ESP32-S3 | توضیحات |
|---------|--------------|---------|
| **T_CS** | GPIO14 | Touch Chip Select |
| **T_DIN** | GPIO11 (MOSI) | (اشتراکی با TFT) |
| **T_DOUT** | GPIO13 (MISO) | (اشتراکی با TFT) |
| **T_CLK** | GPIO12 (SCLK) | (اشتراکی با TFT) |

> **نکته**: تاچ معمولاً با TFT اشتراک SPI دارد و فقط CS جدا است.

### ۳.۳. اتصال ماژول CAN (SN65HVD230)

| پین ماژول CAN | پین ESP32-S3 | توضیحات |
|--------------|--------------|---------|
| **VCC** | 3.3V | تغذیه ماژول |
| **GND** | GND | زمین مشترک |
| **CTX** | GPIO9 | CAN Transmit |
| **CRX** | GPIO6 | CAN Receive |
| **R** | GPIO- | اختیاری (مقاومت ترمینال) |

### ۳.۴. اتصال به CAN Bus خودرو

**روش اول - از طریق OBD-II (توصیه شده):**

پورت OBD-II معمولاً زیر فرمان یا کنار جعبه فیوزها قرار دارد.

| پین OBD-II | علامت | توضیحات |
|-----------|-------|---------|
| **پین ۶** | CAN-H | خط High CAN Bus |
| **پین ۱۴** | CAN-L | خط Low CAN Bus |
| **پین ۴** | GND | زمین خودرو |
| **پین ۱۶** | 12V+ | ولتاژ باطری (برای تغذیه) |

اتصال به ماژول SN65HVD230:
- **CAN-H** OBD-II ← **CAN-H** ماژول SN65HVD230
- **CAN-L** OBD-II ← **CAN-L** ماژول SN65HVD230

**روش دوم - اتصال مستقیم به سیم‌های CAN (فقط برای متخصصان):**

می‌توانید مستقیم به سیم‌های CAN Bus در هر نقطه از خودرو متصل شوید:
- سیم **CAN-H** معمولاً **نارنجی-مشکی** یا **سفید**
- سیم **CAN-L** معمولاً **نارنجی-قهوه‌ای** یا **آبی**

> **⚠️ هشدار**: قبل از قطع باتری خودرو را جدا کنید. اتصال اشتباه CAN-H و CAN-L می‌تواند به ماژول آسیب بزند.

### ۳.۵. تغذیه از 12V خودرو

> مبدل باید حداقل **۱ آمپر** جریان خروجی 3.3V داشته باشد.

## ۴. نصب نرم‌افزار (راه‌اندازی PlatformIO)

### ۴.۱. پیش‌نیازها

1. **Visual Studio Code** نصب کنید
2. **PlatformIO Extension** را در VS Code نصب کنید
3. **Git** را نصب کنید

### ۴.۲. دریافت پروژه

```bash
git clone https://github.com/yourusername/CarTouch.git
cd CarTouch
```

### ۴.۳. کامپایل و آپلود

```bash
# کامپایل و آپلود کد اصلی
pio run -t upload

# آپلود فایل‌های SPIFFS (وب و DBC)
pio run -t uploadfs

# مانیتور سریال
pio device monitor
```

### ۴.۴. کتابخانه‌های مورد استفاده

این کتابخانه‌ها به‌صورت خودکار توسط PlatformIO (بر اساس `lib_deps` در `platformio.ini`) نصب می‌شوند؛ جدول زیر فقط برای مرجع نسخه و مجوز است:

| کتابخانه | نسخه | مجوز | توضیحات |
|---|---|---|---|
| TFT_eSPI | ≥ 2.5.43 | BSD | درایور نمایشگر TFT |
| lvgl | 8.4.x | MIT | کتابخانه رابط کاربری گرافیکی |
| ESPAsyncWebServer | ≥ 3.7.1 | LGPL | وب سرور Async |
| AsyncTCP | ≥ 3.3.0 | LGPL | پشتیبانی TCP Async |
| ArduinoJson | ≥ 7.2.0 | MIT | کار با JSON |
